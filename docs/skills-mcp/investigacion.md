# Ficha de investigación — Skills + MCP (C-02 core-models)

## 1. Necesidad detectada
C-02 (`core-models`, Governance CRÍTICO) crea los modelos y el constraint anti-solapamiento. El riesgo mayor es violar las reglas duras: doble reserva validada solo en UI (RN-TU-01/RN-GL-01), fechas naive, dinero en float (RN-CO-03) y seeds con datos reales (RN-GL-02). Hoy `backend/app/models/` está vacío y no hay guardián automático que bloquee esos errores antes del `/opsx:propose`. Se necesita: (a) una skill que exija EXCLUDE a nivel motor + invariantes, y (b) un MCP que permita inspeccionar el schema real y probar solapamientos con datos ficticios.

## 2. Change elegido: C-02 core-models
Siguiente pendiente del roadmap (C-01 archivado). Scope: `Consultorio/Sillon/Tratamiento/Usuario/Paciente/Turno/Bloqueo/RecordatorioWA/Cobro`, `AuditMixin`, `EXCLUDE USING GIST (sillon_id WITH =, tstzrange(inicio,fin) WITH &&) WHERE (is_active…)`, CHECK `fin>inicio`, índices `(sillon_id,inicio)/(paciente_id,inicio)/(estado,inicio)`, migración 001 + seed ficticio, tests de solapamiento a nivel motor. Leer antes: KB 04 (Entidades/ERD), 05 (RN-TU/RN-GL), 08 (Patrones/capas), 09 (DD-02/DD-05). La skill y el MCP se complementan en este mismo change: la skill dicta la norma, el MCP la verifica viva.

## 4. Comparación de 2 MCP y elección justificada
| | **Postgres oficial `@modelcontextprotocol/server-postgres`** (elegido) | **Context7 (ya conectado)** |
|---|---|---|
| Qué hace | Servidor local, acceso **solo lectura** a Postgres: recurso `schema` por tabla + herramienta `query` (transacción `READ ONLY`). | Servidor remoto de documentación: trae docs oficiales y ejemplos versionados. |
| Aporte a C-02 | Verifica lo que la skill exige: `\d turno`, `SELECT * FROM pg_constraint`, intentar doble insert y ver `exclusion_violation`, contar seeds. Sin él, EXCLUDE solo se revisa en texto. | Respalda el diseño (`EXCLUDE`, `rangetypes`, `btree_gist`) pero no toca la DB. |
| Riesgo | Medio-bajo: read-only por diseño, pero una `query` pesada (`SELECT *`) puede degradar; se mitiga con `LIMIT`, timeout y URL de test. | Bajo: solo lectura de docs públicas. |
| Por qué gana Postgres | Es el único que **comprueba el invariante en el motor** (RN-TU-01/RN-GL-01). Context7 queda como apoyo (ya conectado y usado para `rangetypes`). Ambos se complementan con la skill en C-02. |

## 5. Instalación / configuración (cliente: opencode)
Servidor (según `modelcontextprotocol/servers` y npm `@modelcontextprotocol/server-postgres` v0.6.2): `npx -y @modelcontextprotocol/server-postgres <DATABASE_URL>`; requiere Node 18+ y `DATABASE_URL postgresql://turnos:turnos@localhost:5432/turnos_test` (test, jamás prod; sin secretos en repo, solo `.env` local). Cliente opencode (según `opencode.ai/docs/mcp-servers/`): en `opencode.json` → `{"mcp":{"postgres":{"type":"local","command":["npx","-y","@modelcontextprotocol/server-postgres","postgresql://turnos:turnos@localhost:5432/turnos_test"],"enabled":true}}}`. **Comprobar conexión:** `opencode mcp list` debe mostrar `postgres connected` (hoy muestra `context7`+`engram`; `postgres` pendiente porque Docker Desktop está caído 2026-10-16). **Ejecutar herramienta:** pedir `usa postgres para describir la tabla turno` o `usa postgres query: SELECT sillon_id, tstzrange(inicio,fin) FROM turno LIMIT 5`; el agente lista `postgres_query`/`postgres_schema` junto a built-ins. **Consulta vs modificación:** solo `SELECT`/inspección de schema; NUNCA `INSERT/UPDATE/DELETE/DDL` por MCP (el servidor los rechaza por `READ ONLY`); cambios solo vía Alembic + tests. **Límites datos de prueba:** DB `turnos_test` efímera (`docker compose up db`), seeds ficticios KB-04 (Consultorio demo, 2 sillones, Limpieza 30/Control 15/Conducto 60, `paciente.prueba+…@example.com`); prohibidos datos reales (RN-GL-02); `LIMIT 5–100`, timeout 5 s, fuera de horario de demo.
